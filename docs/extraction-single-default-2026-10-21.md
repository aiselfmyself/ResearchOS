## 1. 決定

**抽出型タスクは単独既定とする。**

ここで「抽出型タスク」とは、一次資料から、事前に定めた項目集合の値・所在・逐語を抜き出す作業をいう。既定では、**1人のワーカーがその項目集合全体を担当する**。同じ項目集合を、速くするためだけに複数ワーカーへ分割しない。

この決定は研究上の一般法則ではない。本リポジトリの当面の割当方法を定める、取り消し可能な運用決定である。

## 2. 適用範囲

### 2.1 適用する

- 1本の論文など、1つの一次資料から固定項目を抽出するタスク
- 同じ資料の文脈を共有し、担当者ごとに全文を読み直す形になる、1つの割当単位として切り離せない項目集合
- 「項目を人数分に割れば壁時計が縮むはずだ」という理由だけで分割しようとしている場合

### 2.2 この決定で禁止していないもの

- **独立した複数タスクを並行に走らせること**。たとえば論文 A と論文 B の抽出を別ワーカーへ1編ずつ割り当てるのは、各タスクが単独担当である限り本決定と両立する。禁止するのは、同一項目集合の内部分割である。
- 抽出後の**独立照合・検証**。同じ項目を別のワーカーが誤り検出のために再確認するのは速度目的の分割ではなく、冗長化／照合型の作業である。必要性は別途判断する。
- コード実装、関係裁定、自由作文、統合レポート作成など、抽出型でないタスクの分割。これらについては本実験から結論を出していない。

### 2.3 例外として分割を検討できる場合

次のいずれかがあり、割当文書に理由を先に書く場合に限る。

1. 資料または項目数が、1セッションの文脈・時間・取得上限に対して明らかに大きすぎる。
2. 節・資料・表などにより読解範囲が自然に分離でき、各担当が全文を読み直さずに済むため、読解量そのものが減る。
3. 明確な期限があり、同時投入できる体制と統合手順を用意したうえで、壁時計短縮の見込みを事前に示せる。
4. 分割方法自体を測る再実験として、人間が設計と判定基準を承認している。

例外を使う場合も、担当境界、開始コミット、投入時刻、統合担当を割当時に固定する。

## 3. 割当時の手順

1. まず「これは固定項目の抽出か」を判定する。該当すれば単独ワーカーへ項目集合全体を渡す。
2. 複数の独立した抽出対象がある場合は、項目集合を割るのではなく、**対象ごとに1ワーカー**を割り当てる。
3. 精度が重要なら、最初から項目を分割するのではなく、単独抽出の後に照合タスクを別途置くかを判断する。
4. 例外分割をする場合は、 §2.3 のどれに該当するかと、期待する短縮・統合コストをプロンプトへ明記する。
5. 結果を受けた統合役は、単独／分割の別、開始点、所要時間の記録方法を成果物から追跡できるようにする。

## 4. 実験で観測されたこと

対象は arXiv:2609.37633v2 から51項目を抽出するパイロットで、単独ワーカー1人と、同じ51項目を17項目ずつ層化配分した3ワーカーを比べた。X4 の最終分類は次のとおりである。

| 指標 | 単独 | 3分割 | 解釈 |
|---|---:|---:|---|
| 正解 | 51 / 51 | 51 / 51 | 事実誤り・棄権・欠落は両側0件 |
| M1 壁時計 | 485秒 | 2,062秒 | 定義上の投入時刻は未記録のため代理値。比は4.25倍 |
| M2 セッション総時間 | 200秒 | 1,014秒 | 比は5.07倍。P2 の待機を粗く除いても約3.1倍 |
| ツール呼び出し（自己申告） | 26 | 83 | 比は3.19倍 |
| 出力バイト数（X4実測） | 14,352 | 43,136 | 比は3.00倍 |
| 統合形式の手直し | 0件 | 0件 | JSON 形状・マージ競合の問題は無かった |
| 投入以外の人間介入（事象数） | 1 | 4 | 数え方には幅があるが、調整事象は分割側に多かった |

設計が提案した3分割採用条件は、壁時計0.70倍以下、総セッション時間1.5倍以内などだった。実測はどちらの時間条件も満たさなかった。少なくとも今回の運用環境では、3回の投入、開始条件の確認、停止・再指示、複数PRの処理といった調整コストが、分担による短縮を上回った。

## 5. 実験の限界と、この決定が主張しないこと

このパイロットは厳密な同条件実験としては格が低く、X4 自身が「参考報告」と位置づけている。主な制約は次のとおりである。

- 4セッションの開始コミットが共通ではなく、後発側の作業ツリーには先行アームの出力が存在した。独立性は自己申告に依存する。
- 判定閾値を人間が事前に確定した D2 の独立記録は確認できていない。X4 は設計書の提案値へ照合した。
- プロンプト投入時刻が記録されず、M1 はセッション開始時刻による代理値である。並行側は人間により直列に投入された。
- 両側とも事実誤り0件だったため、誤り率に差があるかどうかは判定できない。「同じ正確さ」が示されたわけではない。
- 各分割ワーカーも全文を航行する層化配分であり、節ごとに読む範囲を分ける方式は試していない。
- 試行は各条件1回で、基盤モデルも統制できていない。

したがって本決定は、「並行抽出は一般に劣る」「分割しても正確さは同じ」という科学的主張ではない。現行の投入・統合方式では、少なくとも同規模の抽出を速くする根拠が得られず、むしろ調整コストが観測されたため、**反証が得られるまで単独を既定にする**という運用判断である。

## 6. 見直し条件

次の条件をそろえた再実験で、分割が事前に承認した時間・誤り・統合コストの基準を満たした場合は、人間が本決定を改定できる。

1. 全セッションを、他アームの成果物を含まない同一開始コミットから立てる。
2. プロンプト投入時刻と待機時間を、人間または機械記録で残す。
3. 判定閾値を結果を見る前に承認・記録する。
4. 単純な明示値だけでなく、誤りが実際に起こり得る難度の項目を含める。
5. 層化配分と範囲分割を混同せず、測る分割方式を分ける。
6. 赤い CI の成果物を実験出力として固定しない。

再実験をしない場合でも、投入の同時化、統合の自動化、対象規模の拡大など運用条件が大きく変われば、人間判断で見直してよい。その場合は本書を上書きして履歴を消すのではなく、後継文書または改定記録で、変更日・理由・根拠を示す。

## 7. 関連する決定との境界

- 本決定は `rho` / `c` の直接測定の凍結を変更しない。共通誤り0件を相関誤りの推定には使わない。
- 本決定は、独立タスクを複数ブランチで並行開発することや、CI が緑の PR を自律マージする方針を変更しない。
- 本決定は、抽出結果を推測で埋めてよいという意味ではない。見つからない項目は棄権し、探した範囲を記録する従来の規約を維持する。
