# 未完了項目のワーカー割当プロンプト（2026-10-21）

## この文書の使い方

以下の各プロンプトを、**別々のワーカー／セッションに1件ずつ**渡す。A〜C は優先度高、D〜E は独立して進められる追加の文献調査である。A〜E は別成果物にするため並行実行できる。

全ワーカー共通の注意：

- 成果物は指定された自分用の `contributions/` ファイル1本だけに書く。既存文書、`README.md`、`state/`、`tests/fixtures/`、コードは変更しない。
- `state/` への登録や既存資料の訂正が必要と思われる場合は、変更せず、提案・根拠・引用位置を報告する。ID は統合役が採番する。
- GitHub の Issue / PR を作成・変更・クローズしない。GitHub 状態の確認が必要な場合は読み取りのみ。
- 出典の主張とワーカー自身の推論を明確に分ける。一次資料を見ていない点は「未確認」と明記し、推測で埋めない。
- 完了時に、作業内容、未完了・ブロッカー、実行した検査と結果を成果物に記す。

## ワーカー C（優先度高）：RRSI 原典レビューと暫定実装の評価

```text
あなたは ResearchOS の RRSI 文献レビュー担当です。日本語で報告してください。

## 目的

## 確認先
- https://arxiv.org/abs/2609.24972
- https://arxiv.org/html/2609.24972v3
- 公式コードとして論文または abs ページが示すリンク先（リンク先が公式と確認できた場合のみ）

本文で特に確認する項目：
1. proposer の temporally annealed budget：定義、実装、予算を変える規則、実験上の役割。
2. critic：benchmark-specific な提案の判定方法、採否のどの段階で機能するか、具体的な入力・出力。
3. pruner：too small / too expensive / no longer useful の意味、判定尺度・閾値・評価頻度。

5. 性能とコストの採用基準、報告された「30% fewer policy tokens」の条件・比較対象。
6. 本リポジトリの現行ツールとの対応と相違：holdout_eval は検査器の一般化を測り、prune_candidates は使用状況の代理指標を報告する。これらを原典の機構と同一視しない。

`holdout_eval.py` と `prune_candidates.py` をそれぞれ「妥当」「要修正」「RRSI実装とは呼ばず別用途で維持」「撤回候補」などに分け、本文根拠を添える。原典機構のうち、モデル学習なし・少人数セッション・決定論的CIの ResearchOS で実現可能なものと、実現できない／実験条件が足りないものを区別する。コードや台帳を変更する提案ではなく、統合役が判断できる設計案にする。

- ソースの記述と自分の適用判断を分離し、引用には節・ページ・URLを付ける。取得できなかった箇所は明記する。
- 既存スクリプト、テスト、CI は編集しない。

`contributions/2026-10-21_rrsi_fulltext_review.md`
```
