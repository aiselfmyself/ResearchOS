## 1. 決定

**監査 ID 18 を凍結する。**

ID 18 は未解決である。ただし、現行の ResearchOS の運用で解決を試みる作業は割り当てない。これは放置や失念ではなく、人間が意図的に停止した項目として扱う。

人間の判断理由は、**本リポジトリの運用が Arena.ai の Agent Mode を前提としており、ID 18 が必要とする統制要件を満たすことが困難である**ことにある。

## 2. ID 18 が求めていたもの

ID 18 の完了条件は、単にモデルとハーネスの両方に触れた論文を見つけることではない。少なくとも次を備えた一次資料または実験が必要だった。

1. 同一タスク・同一評価条件であること。
2. 複数のモデル能力水準と複数のハーネスを、区別できる形で変えていること。
3. モデル差とハーネス差を分けた数値があり、効果比 R を計算できること。
4. 予算、評価手順、provider、タスク集合などの交絡を、解釈可能な程度に固定または開示していること。
5. 既存の 2 系統とは独立な第3の観測として、閾値 R ~ 1 の枠組みとタスク領域依存性を区別できること。

凍結時点までに得られた到達点は次のとおりである。

- 既存文献インベントリには、要件を完全に満たす論文は無かった。
- 追加探索でも、完全に満たす論文は見つからなかった。
- GAIA 系候補は格子を持つが、既存比較とタスク領域や条件が異なる。
- SWE-bench Pro 系候補はモデル×ハーネスの格子に近いが、必要数値が本文テキストではなく図にあり、分散分解や R 型指標は論文側に無い。
- 候補 B・C は観測データに基づく分析で、統制格子の分散比ではない。
- 候補 D は 2 モデル・各セル n=50 で、信頼区間が広く、表の内部不一致もある。
- したがって「R ≈ 1」は検証済みではなく、タスク領域・評価方式・予算・provider などの交絡も未解消である。

詳細は [`contributions/2026-10-21_id18_paper_search.md`](../contributions/2026-10-21_id18_paper_search.md) に残す。

## 3. なぜ現行運用では凍結するか

### 3.1 自前の統制比較を作る場合

ID 18 を満たす証拠を自前で作るには、モデル、ハーネス、プロンプト、ツール、タスク集合、評価手順、計算／トークン予算、開始状態、反復、独立性を固定し、それらを後から検証できる必要がある。

現在の Arena.ai Agent Mode を前提にした運用では、少なくとも次を十分に統制・検証できない。

- 各セッションの基盤モデルと版を、割当側が指定・確認すること。
- 複数セッションを同時・同一開始コミット・同一環境で開始すること。
- セッション間の独立性を、指示と自己申告だけでなく実行過程から検証すること。
- provider、取得経路、応答条件、投入時刻、待機時間、予算消費を完全な生ログとしてそろえること。
- 同一条件で必要な反復数を実行し、モデル／ハーネス以外の変動を分離すること。

単独対並行パイロットでも、開始コミットの不一致、直列投入、投入時刻の未記録、基盤モデルの不明が実際に生じた（[`contributions/2026-10-21_svm_results.md`](../contributions/2026-10-21_svm_results.md) §6）。したがって、現行運用で「統制実験」と呼べる証拠を作ることは困難である。

### 3.2 文献探索を続ける場合

文献を探すこと自体は可能である。しかし ID 18 の目的は候補数の増加ではなく、統制の取れた第3の観測によって R の枠組みを検証することにある。

これまでの探索で得られたのは、観測研究、部分的な格子、モデル数が少ない研究、数値が図にしかない研究などであり、追加の抽出だけでは各研究内部の統制不足や交絡は解消しない。同じ方法で候補を増やしても、部分的な観測を「検証済み」に近づけたように見せてしまう危険がある。

したがって、現行運用では ID 18 の解決を目的とした追加探索も凍結する。これは「要件を満たす論文が世界に存在しない」という主張ではない。

## 4. 凍結する作業・しない作業

### 4.1 凍結する

人間が再開を決定するまで、次を割り当てない。

- ID 18 を解決するための新しい論文探索。
- 既存候補の図中数値の抽出や追加本文確認を、ID 18 の判定更新目的で行うこと。
- Arena.ai Agent Mode のセッションを使って、モデル×ハーネスの統制比較を自前で実施すること。
- `docs/worker-assignment-prompts-2026-10-21.md` のワーカー B プロンプトを新規に投入すること。
- 部分的な観測の追加だけを理由に、ID 18 を「解決」や「検証済み」へ変更すること。

### 4.2 凍結しない

次は通常の保守・研究記録として扱ってよい。

- 既存の ID 18 メモ、SRC、EVD、VER、REL を読み、引用すること。
- 壊れた参照、件数、ゲート不整合など、既存記録の保守。
- `HYP-20261021-9f99` を `proposed` の仮説として保持すること。ID 18 の凍結は、この仮説の採択でも棄却でもない。
- 別の正当な研究作業の過程で、要件を満たしそうな一次資料に偶然出会った場合に、その存在を人間へ報告すること。ただし ID 18 の再開・精読・抽出は、人間の再開決定後に限る。

## 5. 再開条件

再開は自動では行わない。**人間が明示的に再開を決定すること**に加え、次のいずれかの経路が具体化している必要がある。

### 経路 A：要件を満たす外部一次資料が具体的に示される

- 同一タスクで、複数能力水準×複数ハーネスの格子がある。
- 各セルの数値を一次資料から取得できる。
- 評価手順、予算、反復、不確実性が解釈可能な形で開示されている。
- 再開後の抽出は、抽出型タスクの単独既定に従い、まず 1 ワーカーが項目集合全体を確認する。

### 経路 B：統制可能な実行環境が用意される

- モデル／版、ハーネス、プロンプト、ツール、タスク、予算、開始状態を固定できる。
- 独立性、投入時刻、反復、生ログを検証できる。
- 項目、除外規則、R の計算方法、判定閾値を結果を見る前に承認・記録できる。

### 経路 C：問い自体が再定義される

- 人間が、統制された因果識別を求めない文献地図や観測研究の整理など、現行運用で答えられる問いへ ID 18 を置き換える。
- この場合も、旧 ID 18 を解決済みにせず、新しい問いと完了条件を別に記録する。

## 6. 凍結時点の主張の扱い

- 「R ≈ 1」は作業仮説であり、検証済みの法則ではない。
- `HYP-20261021-9f99` は `proposed` のままである。
- 既存 EVD への REL は、各観測が仮説とどう関係するかを示す裁定であり、ID 18 の解決を意味しない。
- 凍結は証拠の削除や格下げではない。到達点と限界を保持したまま、追加作業を止める決定である。
