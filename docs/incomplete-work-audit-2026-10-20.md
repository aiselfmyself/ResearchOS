### 13.1 ハーネス硬化の優先順位（2026-10-20 の判断）

2026-10-20 の統合レポート重複（PR #17 と PR #18 が同一の `task/TASK.md` §4 を二重に作成）を受け、
ハーネス硬化を P0／P1／P2 に分けて検討した。

| 優先度 | 内容 | 判断 |
|---|---|---|
| P0 | タスク宣言レジストリ（着手前にタスクを宣言し、二重宣言を CI で検出） | **見送り** |
| P1 | 参照解決検査・`check_memo_citations.py` の CI 接続と黙読スキップの排除 | **実施**（本節 ID 8、および PR #21） |
| P2 | 検証ブロックの機械実行化・文献IDのグローバル化 | 未判断 |

**P0 を見送った理由**（2026-10-20、人間による判断）：同一タスクへの二重着手が発生しても、
それは「**二重の独立したトライアル**」と解釈できる。統合レポートの形で両者を突き合わせる
こと自体が**検証フェーズを兼ねるため、むしろ利点**になり得る。

この判断に基づき、**検証ランとして並列稼働実験**を設計した（E1: ハーネス検証＋E2: 誤り相関 `rho`/`c` の観測）。
手順は `docs/parallel-session-playbook-2026-10-20.md`、設計と3セッション（A / A' / B）への
タスク割り当ては `docs/parallel-experiment-2026-10-20.md`。

- **A と A' は同一タスク**（arXiv:2609.18094 の全文読解）を**独立に**解く。これが `rho` の観測になる
- **B** は2出力から一致率と lift（相関誤りの倍率）を計算するツールを作る
- **交絡の明示**：A と A' は同じ論文を読むため、`rho`（ワーカーの均質性）と
  `c`（共有入力への追従）が**分離できない**。合成値を測り、交絡を明示して報告する
- **検出力の明示**：セッション数は n=1 であり、存在証明の域を出ない

**結果（同日実施、[`contributions/2026-10-20_parallel_experiment_results.md`](../contributions/2026-10-20_parallel_experiment_results.md)）**：

- **E1（ハーネス）は成功**。3セッションすべてが同一の分岐元から開始し、**マージ競合0件**、
  競合解消コミット0件、統合役専用パスは未変更、CI は3本とも pass、変更ファイルは完全に排他的だった。
  ブランチ巻き戻りも観測されなかった。効いたのは**パスの排他的割り当て**
  （`tests/test_minimal_core.py` を明示的に禁止したことが特に効いたと考える）。
  **ただし n=1 であり、パス規律を守る運用に依存している。プレイブックに強制力はない。**
- **E2（誤り相関）は測定できなかった**。単一の正解を定められる8項目で**両セッションとも全問正解、
  誤り0件**となり、`lift` は undefined（独立時の期待値 p1*p2 が0になるため）になった。
  「相関誤りは観測されなかった」とは言えるが、「相関誤りはない」とは言えない。
- **副次的に、実験設計と計測器の不備が4点見つかった**（自由選択項目・数え方の未定義・
  文字列比較・一致率の過小評価）。これが本次の最も実用的な成果である。

この判断は本研究の主題（同質ワーカーの並列化が独立した証拠を増やすか）にも関係する。
2つの独立セッションが同じ成果物を生成する事象は、**ワーカー間の誤り相関 `rho` の観測例**
と読める。統合時に両者を比較することで、相関の有無を実際に観察できる。
（ただしセッション数は少ないため統計的検出力は極めて低い。存在証明の域を出ない。）

### 13.2 並列稼働実験の事後対応と凍結（2026-10-20）

E1／E2 の結果を受けて、統合役が3つの未解決判断を人間に諮った。判断と実行結果は次のとおり
（詳細は [`contributions/2026-10-20_parallel_experiment_results.md`](../contributions/2026-10-20_parallel_experiment_results.md) §6）。

| 論点 | 人間の判断 | 実行結果 |
|---|---|---|
| 2本の読解レポート（A / A'）の扱い | **統合する** | `contributions/2026-10-20_agora_integrated_reading.md` を作成。**元の2本とその `.json` は削除しない**（E2 の生データであり、計測器 `scripts/measure_agreement.py` の入力でもある） |
| 版の扱い | **最新の v4 を確認する** | 実施。**v1 から実質的な差分があった**（下記） |
| 実験の継続 | **凍結する**（データが蓄積した時点で再実験） | `docs/parallel-experiment-2026-10-20.md` §6 に凍結を記録。統合役は追加の複製セッションを起こさない |

**v4 の確認で判明したこと**（統合レポート §1 に全件記録）：

1. 要旨の数値は v1 と v4 で**完全に一致**（13 workers、1,703、3.3923→1.899044、62%、145/15、165/95）。
2. **「並行再発見」が撤回された**。696 組 → **523 組**に訂正され、見出しが `Parallel rediscovery` から
   **`Equal-score convergence`** に変更。本文に「independent rediscovery ではなく**同じ結果への収束**」と明記。
   → 本実験が「最も近い実例」の根拠として挙げた観測は、著者自身により**相関の証拠ではない**と読み替えられた。
3. **人間の介入が v1 の記述より大幅に多い**。サーバ3回変更＋プロンプト1回変更、**8ワーカーへの個別指示**、
   **著者が手動で動かしたセッション3回（うち1回は最良 contribution の祖先に含まれる）**、DB の直接編集、
   クラスタ閾値の恣意的設定。そして **「No separate intervention log survives」**。
   A が v1 から読んだ「個別セッションへの指示はしていない」は、v4 で実質的に撤回されている。
4. **v4 §4.2 が相関を生む機構を初めて名指しした**：8台の H100 ワーカーは**同一ノード上の別コンテナ**で、
   ファイルは共有しないが**互いのプロセスを一覧できた**。「**勝者モジュールを含む**複数の記述が、
   隣のワーカーが走らせているスクリプトを見て実験を選んだと報告している」。
5. v1 §5 の因果留保（"What the run does not settle is causal: we did not run the same models and compute
   without Agora or with a plain leaderboard"）は **v4 §5 には無く**、"establishing its effect on discovery
   efficiency requires matched comparisons across tasks" という穏やかな表現に置き換わっている。
   → **v4 は本文（§4.7）で介入の開示を増やす一方、結論（§5）の留保を弱めている。**

**本研究への含意（§13.1 の結論を更新）**：Agora は ρ の**測定値としては使えない**（これは v1 でも同じだが、
v4 は「投稿されなかった再現試行は痕跡を残さない」と明記したため、検証 165 件・失敗 0 件が信頼性の証拠に
ならないことがより明確になった）。一方で v4 は「独立に見える並列実行が、同一ノードでのプロセス可視性により
実際には独立でない」ことを**実例として示した**点で v1 より有用である。これは `gitswarm/readout_sim.py` が
置く「同質ワーカー」の前提、および CLM-003（`candidate` のまま）を裏付ける。

**再開時に先に直すべきもの**（計測器の設計不備4件）：(1) 答えが一意に定まる項目にする、
(2) 「いくつあるか」を問う項目には数え方の規則を定義する、(3) 値は意味的に比較する、
(4) 素の一致率には必ず不一致の内訳を併記する。加えて**対象文献の版を固定してから配る**こと
（今回、版を固定しなかったために v1 を読んだ2セッションの記述が v4 で一部陳腐化した）。
