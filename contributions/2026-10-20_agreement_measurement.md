## 1. 何を測る道具か

**同じタスクを2つの独立セッション（A と A'）が解いて出した抽出結果を突き合わせ、(i) どこで一致したか、(ii) 正解が与えられたとき誤りが相関しているか**を測る。本実験の未解決事項1位である `rho`（ワーカー間の誤り相関）の観測装置である。

入力はプレイブック §4 形式の JSON 2つ（`--a`, `--b`）と、任意の正解ファイル（`--truth`）。出力：

1. **項目ごとの判定**：`agree` / `disagree` / `both-missing`。加えてカバレッジの欠落を隠さないため `a-only` / `b-only`（片方にしか項目が無い）を出す。この2つも「一致していない」として一致率の分母に入る。
2. **一致率**：`agree / 全項目`（全項目 = A・B・truth の id の和集合）。比較可能項目だけの率（`agree / (agree + disagree)`）も併記する。
3. **Cohen's kappa**：値を名義カテゴリとした値レベルの kappa。偶然の一致を差し引いた一致の程度。
4. **`--truth` 指定時のみ**：各ワーカーの誤り率 `p1`, `p2`、実際に両者が同時に誤った割合 `P(both wrong)`、独立なら期待される `p1 * p2`、および **lift = P(both wrong) / (p1 * p2)**。

**lift の読み方**は `gitswarm/readout_sim.py` の増幅率と同じである。「独立なら `p1*p2` のはずが、実際にはそれより高い」＝誤りが相関している。`lift > 1` は正の相関、`lift = 1` は独立と整合、`lift < 1` は誤りが互いに素（偶然より同時誤りが少ない）、`p1` か `p2` が 0 のとき lift は未定義（null）と報告する。

## 2. 判定と分母の定義（ここが計測の前提）

| 対象 | 判定 |
|---|---|
| 両者が値を出し、比較規則の下で一致 | `agree` |
| 両者が値を出し、一致しない | `disagree` |
| 片方が `unknown`/`null`（棄権）、もう片方が値を持つ | `disagree`（注記で棄権を明示） |
| 両者が棄権、または両者から項目が欠落 | `both-missing` |
| 片方だけに項目が存在 | `a-only` / `b-only` |

**`unknown` / `null` は棄権として別扱いする**（誤りでも正解でもない）。ここを雑にすると lift が歪む。本メモ §3 の実例では、棄権2件を誤りに数えると lift が 1.5 → 1.25 に動く。分母の項目集合が変わるためである。

**誤り率と lift は「両者が決定した部分集合」（joint-decided subset：truth が既知かつ両者が値を出した項目）上で定義する。** `p1`, `p2`, `P(both wrong)` がすべて同じ母集団の比率になるため、独立帰無仮説 `p1 * p2` が周辺確率の積として厳密に意味を持つ。各ワーカーが自分が決定した全項目で計えた誤り率（`error_rate_all_decided`）を文脈用に併記するが、lift の計算には使わない。

## 3. 比較の実装方針

- **数値項目**：許容誤差で比較（既定 `1e-6`、`--tol` で変更）。`bool` は数値の前に判定し、`True == 1` を許さない。
- **文字列項目**：空白の折叠（全空白を1文字に）と case-folding の後に比較。
- **リスト項目**：多重集合として順序を無視して比較（各要素がちょうど1回ずつ消費されるよう貪欲に照合）。
- **型は厳格**：`"42"` と `42` は不一致。抽出の型の取り違えは丸め差ではなく実質的な不一致なので、黙って変換しない。
- **kappa のカテゴリ**：正規化した値そのものを名義カテゴリとし、数値カテゴリは `--tol` の格子に量子化して `pe` が許容誤差を尊重するようにする。観測一致率 `po` は判定（verdict）から取る（権威は判定側）。両者が値を出した項目だけが rated に入る。

## 4. 何が測れないか（この道具の限界）

1. **正解が無いと正誤は測れない。** `--truth` が無いとき出力できる是一致率と kappa のみ。そして**一致率高 ≠ 正しい**。両者が同じ誤りをすれば一致率は高く lift も上がる。Agora の抽出では本文に書いていない推測に `location: null` を付ける規約があるが、両者が同じ推測をした場合、この道具には「同じ推測」か「同じ誤り」かは区別できない（truth がない限り）。
2. **項目は `id` で突き合わせる。** `label` ではない。id がずれていれば別項目として扱われ（宇宙に2つ存在するように見え）、一致率は下がる。プレイブック §4 の id 規律が前提である。
3. **kappa は正規化・量子化に依存する近似。** 数値カテゴリの格子化は許容誤差境界で同値関係を壊しうる。境界事例では生の件数（`po`, `pe`, `n_rated`）を必ず併読すること。
4. **lift は両者が決定した項目でのみ定義される。** 棄権が多いと joint subset が小さくなり、解釈は更に脆くなる。棄権の**理由**（本文に無いのか、読み落としなのか）はこの道具には測れない。
5. **リストの許容誤差比較は貪欲照合**なので、理論上は推移的でない境界事例がありうる（文字列・真偽・厳密な数値では発生しない）。
6. **区間推定は出さない。** lift は点推定のみで、信頼区間も p 値もない。n が小さいときの「1を超えた」の意味は §6 の但し書きに委ねる。

## 5. 交絡についての但し書き（実験ドキュメント §1 から必須）

A と A' は**同じ論文を読む**。つまり入力が共有されている。これはモデルの `c`（共有見解への追従）チャネルそのものであり、`rho`（ワーカー自体の均質性）と**分離できない**。

この道具が観測できるのは **`rho` と `c` の合成効果**である。したがって「lift > 1 だったからワーカーが同質（rho が高い）」とは**言えない**。共有入力への追従（c チャネル）かもしれないし、モデル自体の均質性（rho チャネル）かもしれない。分離には「入力を重ならせない」条件が必要だが、このリポジトリでは全メモが `contributions/` に集約されているため現実的でない。**分離できていないものを分離できたと言わない**（`docs/parallel-work-ownership.md` §1 の方針）。

## 6. 検出力についての但し書き（必須）

セッション数は **n = 1**（A と A' の1組）。**統計的検出力は極めて低く、存在証明の域を出ない。** 有意な相関の推定値は得られない。得られるのは「同じ誤りが実際に起きたか」の観測である。

このことは道具側でも明示する：joint-decided 項目数 `n_joint` が 30 未満のとき、実行時に必ず `WARNING: statistical power is very low; lift is an observation, not an estimate` を出す（§7 の実測値でも出ている）。閾値 30 は道具の内部定数（`MIN_JOINT_N`）であり、統計的な正当化ではなく「小さすぎる点推定を静かに出さない」ための注意書きである。

## 7. 検証：テストで固定した4パターン（他に回帰を追加）

`tests/test_measure_agreement.py` は合成データで期待値を固定する（2026-10-19 監査の教訓に従い、リポジトリの履歴にも他セッションの成果物にも依存しない）。

| パターン | 構成 | 期待値（固定値） |
|---|---|---|
| 完全一致 | A = B（5項目） | 一致率 1.0、kappa 1.0（po=pe=1 の退化ケースは 1.0 と定義） |
| 完全不一致 | 値集合が交わらない5項目 | 一致率 0.0、po=0・pe=0 なので kappa 0.0 |
| 独立な誤り | 8項目、A は {1,2,5,6} で誤り、B は {1,3,5,7} で誤り | p1=p2=0.5、P(both wrong)=0.25、期待値 0.25、**lift = 1.0** |
| 相関した誤り | 同じ4項目 {1,2,3,4} で両者誤り | p1=p2=0.5、P=0.5、期待値 0.25、**lift = 2.0** |
| 棄権の除外 | i4 で A 棄権、i5 で両者棄権 | joint subset = 3項目、p1=1/3、p2=2/3、**lift = 1.5**（棄権を誤りに数えると p1=0.6, p2=0.8, P=0.6, lift=1.25 に歪む） |
| kappa の罠 | A は常に "x"、B は 6回 "x" + 4回 "y" | 生一致率 0.6 だが pe=0.6 で **kappa = 0.0**（偶然補正が効いている） |

加えて：真偽値と数値の非等同（`True ≠ 1`）、文字列の空白・大文字小文字正規化、リストの順序無視、`"none"` は棄権でない（ライセンスの実回答）、truth にしか無い項目は `both-missing` で分母に入る、`--tol` の効能、CLI の終了コード 0（入力ファイルが無くても 0）。

## 9. 提案（このメモでは実行していない）

1. **A / A' の実データで走らせ、lift を実測する。**統合役の作業である。
2. **複数ペアが貯まったら区間推定へ。**bootstrap で lift の区間を出す拡張が次の段階として自然である（現状は点推定のみ、§4-6）。
3. **棄権の理由を別項目として記録するなら、道具に渡す前に正規化する。**例えば `location: null` を「本文に無い」と解釈するかは人間の判断で、この道具は値の棄権しか見ない。
