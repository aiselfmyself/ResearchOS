## 2. E2: 誤り相関の観測 — **誤りが1件も発生しなかった**

### 2.1 計測器の生の出力

```text
Verdict counts: agree=8 disagree=6 both-missing=1
Agreement rate (agree / all items):        8/15 = 0.533
Agreement rate (comparable items only):    8/14 = 0.571
Cohen's kappa (value-level):               0.551
```

一見すると「一致率53%」は低い。しかし**内訳を見ると実態は違う**。

### 2.2 不一致6件の内訳（私が中身を精査した）

| 項目 | A | A' | 実際は |
|---|---|---|---|
| B2 | `Weight-transfer task（FineWeb-Edu 200 テキストの開発評…` | `weight-transfer task` | **同じ事実**。A が説明的な括弧を付けただけ |
| C1 | `1.899044 bpb（ランダム初期化 3.3923 bpb、学習済み GPT-2 124M…` | `Best transfer(): 1.899044 bpb` | **同じ事実**。A の文字列は A' の値を含んでいる |
| C2 | 検証165件／対象95件／失敗0件 | ランダム初期化 3.3923 bpb | **どちらも正しい別の事実**。項目が「代表値を3つ」と自由選択だったため |
| C3 | 最初の18件で総改善量の約98% | GPT-2 124M との差の62%を閉じる | **同上**。自由選択による取り違え |
| E2 | `false` | `true` | **項目の仕様があいまい**（「実行回数」＝コミュニティ走行の回数か、反復試行の回数か） |
| F1 | `3` | `6` | **項目の仕様があいまい**（限界章は存在せず本文中に分散。何を1件と数えるかが未定義） |

**つまり6件のうち、事実の食い違いは0件である。** 2件は書式差、2件は自由選択による取り違え、2件は項目定義の不備だった。

### 2.3 正解データによる誤り率

単一の正解を定められる8項目（A1–A5, B1, D1, E1）について、統合役が v1 の要旨と両メモから正解を確定し、再度計測した。

```text
Items with known truth: 8
  worker_a: decided 8 (correct 8, wrong 0) -> error rate = 0.0
  worker_b: decided 8 (correct 8, wrong 0) -> error rate = 0.0
  p1 = 0.0
  p2 = 0.0
  P(both wrong) = 0.0
  lift = undefined（少なくとも一方の誤り率が0のため、独立時の期待値 p1*p2 が0になる）
```

### 2.4 結論

**`rho` も `c` も推定できなかった。誤りが1件も発生しなかったからである。**

これは失敗ではないが、**観測できたとも言えない**。実験設計書 [`docs/parallel-experiment-2026-10-20.md`](../docs/parallel-experiment-2026-10-20.md) §1 で予告したとおり、n=1・正解可能8項目という規模では、存在証明すら危うい。**「相関誤りは観測されなかった」とだけ言うのが正確**であり、「相関誤りはない」とは言えない。

なお計測器はこの状況を正しく扱い、`lift` を undefined としつつ「n_joint=8 < 30: 統計的検出力は非常に低い」と警告を出している。0除算をごまかさない実装になっている。

## 3. 実験で分かった、実験設計と計測器の改善点

これが本次の**最も実用的な成果**である。

1. **自由選択の項目は不一致を生むが、それは誤りではない。**
   「代表値を3つ」のような項目は、両者が正しくても食い違う。次回は項目を**指定式**にする（例：「§4.5 の best transfer の値を報告せよ」）。
2. **「〜の数」は数え方を定義しないと測れない。**
   F1（限界の数）で 3 vs 6 が出たが、どちらも間違いではない。数える対象を定義するか、項目自体をやめる。
3. **値の比較は文字列ではなく意味で行うべきである。**
   B2・C1 は同じ事実を書いているのに不一致と判定された。列挙型・数値・日付に項目を絞るか、意味的な比較を入れる必要がある。
4. **したがって「一致率」は過小評価になりうる。**
   生の 0.533 は実際の一致の程度を表していない。計測器の出力には**必ず不一致の内訳点评が要る**。

## 4. 研究上の副産物：Agora は本研究に最も近い実例だった

これは本実験の副次的な発見だが、統合レポートの未解決事項に直結する。

Agora は **13の言語モデルワーカーが、割当も中央プランナーもなしに、Git の追加専用 DAG を共有記憶として12日近く走行**した記録である。これは `rho` / `c` の問い——「同質ワーカーの並列化は独立した証拠を増やすか」——が想定している状況そのものであり、今回の文献群の中で**最も近い実例**である。

注目すべき点が2つある。

- **検証の信頼性**：参加者は「作者以外のアカウント」により95件の対象へ165件の検証を行い、**失敗報告は0件**とされる（要旨）。検証が独立的に行われている点は本研究の関心と一致するが、**失敗が1件も出ない**という結果自体は、検証の検出感度を吟味する価値がある。
- **因果の未分離**：著者自身が「計算量あたりの発見への効果を測るには matched comparison が要る」と述べている。つまり Agora 自身も `rho`/`c` を測定していない。

**Agora の走行データは、実ワーカー群における相関誤りを測る一次資料になり得る。** ただし論文はその値を報告していないため、著者がデータを公開しているか確認する必要がある（本実験の G1 項目では A・A' とも判定を保留しており、未解決）。
