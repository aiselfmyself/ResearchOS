作成日：2026-10-21。実装対象は `scripts/score_extraction.py`、合成テストは
`tests/test_score_extraction.py`。実験や一次資料の読解、実際の真値作成は行っていない。

## 設計の根拠と承認

`docs/single-vs-multi-experiment-2026-10-21.md` を参照する。
main の設計書が提案表記だったため、この実装セッションで人間に確認した。
人間は「現行設計を承認して進める」を選択し、項目配分・M1〜M4・§11の
提案値を含む現行設計へのD2承認を明示した。設計書自体は変更していない。
本計測器は閾値による運用採否を自動判定しない。

## 比較規則と実装判断

`measure_agreement` の `values_equal`、`is_abstention`、既定許容誤差をimportする。
既存の集計パイプラインは分母・項目集合・目的が違うので使わない
（新スクリプトのdocstringにも記載）。数値の絶対誤差、文字列の空白圧縮と大小無視、
リストの多重集合比較、boolと数値の区別をそのまま引き継ぐ。
リストの許容誤差境界での貪欲照合という既存の制約も引き継ぐ。

設計の「正解」と「書式差のみ」は正規化範囲が重なるため、同型で字面まで同じなら
正解、比較規則では同値でも字面・順序・数値表記が違えば書式差候補、と操作化した。
末尾句読点だけの差も書式差候補にする。意味や句読点の役割の最終判定はX4が行う。

設計の「%記号残存は書式差」と、今回の「型不一致は不一致」は衝突しうる。
例えば真値10に対する文字列`"10%"`は型変換せず事実誤り**候補**とし、
各行の注記でX4に書式差候補の確認を求める。数値文字列を自動的に正解にしないためである。
慣用表記は真値項目の任意 `variants` リストで明示できる（設計に名前がないため採用した
補助キー）。canonicalな真値とのJSON型が異なるvariantでは一致させない。
`unknown` は棄権と手直し候補の両方に載る。値フィールド欠落はnullと同一視せず
入力エラーにする。行自体の欠落だけが採点上の欠落である。
重複IDは先勝ちにせず入力エラー（担当別集計の曖昧さと見落としを避けるため）。
base_commit の文字列差は警告とし、短縮ハッシュが同じコミットかはX4が照合する。

## 実行方法と補助入力

```sh
python3 scripts/score_extraction.py --outputs single.json p1.json p2.json p3.json --truth truth.json
python3 scripts/score_extraction.py --outputs single.json p1.json p2.json p3.json --truth truth.json --json
```

ログは通常は設計どおり各出力に埋め込む。別ファイルの場合だけ、出力の
`session_log` を外部ファイル名などにして `--logs s-log.json p1-log.json p2-log.json p3-log.json`
を追加する。各別ファイルは§10のオブジェクトそのもの。

M1/M4は§10にデータがないため、任意の `--operations operations.json` を設けた。
未指定・アーム欠落なら該当指標nullであり、0件/0秒ではない。
補助記録の形式は設計が定義していないので以下を入力契約として追加した。
`single`はS、`parallel`はP1/P2/P3をすべて含める。アームごとに次の形を置く：

```json
{
  "single": {
    "workers": {
      "S": {
        "prompt_at_utc": "2026-10-21T00:00:00Z",
        "merged_at_utc": "2026-10-21T00:05:00Z"
      }
    },
    "merge_conflicts": [],
    "repairs": ["ファイル名と項目ID・理由を記録"],
    "human_interventions": []
  }
}
```

配列の1要素を1事象として数える。手直しが項目単位かファイル単位かは各事象に明記し、
同一作業の二重計上を避けるのはX4の責務。並行側も同形式で加える。
全投入・マージ時刻と事象はJSONレポートにも保持する。

## 合成ミニケース・検証

`python3 -m unittest tests.test_score_extraction -v` で実行できる。
すべての真値をダミー数値10、各セッション60秒・呼出3回とした51項目の合成入力で：

- SのQ01を999、Q02を10.0000001、Q03をnull、Q04を行欠落とする。
- S：正解47、事実誤り1、書式差のみ1、棄権1、欠落1。
- M3は1/51、回答済み誤り率は1/49、未回答率は2/51。
- 並行：正解51、合計180秒、呼出9回。Sは60秒・3回。
- 真値との非正解候補4行、アーム間不一致4件が値つきで出る。

別ケースで全件除外・分母0、全件正解、型不一致、許容誤差、列挙の多重度、
句読点・variant、unknownと担当外ID、欠測ログ、外部ログ、M1/M4、共通誤りID、
重複・真値欠落・負時間・非UTC・bool呼出数・種類別不整合・終了コードを検証する。
全8ゲートの実行結果はPR本文に残す。CI設定・既存コード・台帳は変更しない。
