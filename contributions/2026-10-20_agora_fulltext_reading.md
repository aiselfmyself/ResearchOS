## 1. 結論（全文から分かったこと）

1. **主結果は 1 つのコミュニティ走行の系譜である。** 13 体のワーカーが約 12 日間（報告対象 1,703 件の投稿）で、学習データも勾配更新もなしに 119.6M パラメータの凍結ハイブリッドを 3.3923 bpb（ランダム初期化）から 1.899044 bpb まで下げた。学習済み GPT-2 124M（約 1.0）との差の 62% に当たる（§4.5）。主結果を複製した走行は報告されていない。
2. **比較対照が本文で実行されていない。** 手法間のベースライン比較はなく、比較は「ランダム初期化」と「学習済み GPT-2 124M の参照値」だけである（§4.1、§4.5）。Agora 無し・平板ログ・中央計画の 4 アーム比較は Appendix C の**提案**（Table 5）であり、実行されていない。著者は §5 で「因果は未確定」（"What the run does not settle is causal"）と自認している。
3. **選択と評価が同じ開発用評価器上で行われている。** 「every component was selected on the same 200-text development evaluator」（§4.5）。本文に held-out 評価の記載はない。著者も「最後の数桁ではなく改善幅を信頼すべき」と注記している。
4. **「独立な再現」の独立性には範囲がある。** 検証 165 件はすべて作者以外のアカウントによる再実行で、失敗報告は 0 件である（§4.5）。ただし同じ評価器・同じブリーフ・同じリポジトリ上で行われており、著者は勝者の手法そのものを再実行していない（§4.8）。
5. **人間の介入は 1 回だけ**（5 月 2 日、クラスタ表示と多様性考慮 UCB の導入）。介入後に単一の「盆地」から抜けたことは示されているが、対照がないため効果の大きさは測られていない（§4.7、§5）。
6. **多数決は使っていない。** 評価は票ではなく、下流作業による重み付き引用数 S(u)（式 (2)）と自己引用の除外で行う（§3.2、Table 1）。
7. **同一スコアの並行再発見が多い。** 異なるアカウントが同一スコアを投稿した 696 組のうち 63% が 1 時間以内に現れた（§4.6(3)）。著者はこれを共有フロンティアの効果と弱点の両方として提示している。ただし commit 単位の観測は独立サンプルではないと著者自身が注記している（Appendix C）。

## 3. 本文で確認できたこと

### 3.1 問題設定と設計（§1、§3）

- 研究の状態（何を試したか、主張、フロンティア、系譜）を append-only の有向非巡回グラフ（DAG）として Git に保存し、各 contribution の親辺を「builds on」の意味にする（§3.1–3.2、式 (1)）。SQLite の索引は Git 履歴から再構築できる（§3.2、§3.4）。
- 「真偽を決める」ことはしない（"The system does not try to decide what is true", §1）。スコアは「再現・後続利用された結果は行動しやすい」という狭い主張であり、真理の指標ではない（§3.2）。
- Table 1 の設計目標：耐久的な記憶、フロンティアの可視化、証拠の質（投票の否定）、探索の多様性、監査可能性。
- 参加者は CLI または HTTP API で投稿し、ファイルシステムも会話も共有しない（§3.2）。
- 多様性：単連結クラスタ（コサイン閾値 0.90、埋め込み被覆 50% 以上、直近 5,000 件を対象）、式 (3) の多様性考慮 UCB、三つの枠（exploit／explore known／explore novel）（§3.3）。
- 実装：Go サービス＋CLI＋Next.js の Web、プロジェクトごとの bare リポジトリ、SQLite の 8 テーブル、HTTP ルート 26、CLI のコマンド群 15（§3.4）。

### 3.2 タスクと評価器（§4.1）

- 対象：141 個の open-weight 事前学習モデル（534 GB、32 アーキテクチャ族）をドナーとし、どれとも次元が一致しない 14 層・隠れ次元 672・7 ヘッド・119,572,320 パラメータのハイブリッド（attention と簡略化 Mamba 型 SSM の交互配置）を初期化する。
- 制約：ターゲットに対して学習データを使わず、勾配更新もしない。評価器は seed 42 で、FineWeb-Edu の 200 テキストを 512 トークンの非重複チャンクに分け、GPT-2 トークナイザで UTF-8 バイト当たりの損失を測る。FineWeb-Edu の読み込みは `transfer()` の内部から呼ぶと例外になる（§4.1）。
- 基準値：ランダム初期化 3.3923 bpb、学習済み GPT-2 124M 約 1.0。ブリーフの目標は 2.5 未満（"aspirational"）（§4.1）。
- 再現性：同一コード・同一ハードは bit-identical。GPU の型が違うと第 3 位小数が変わる（§4.1）。

### 3.3 エージェントと運用（§4.2–4.3）

- 実行系：Claude Code（Claude Opus 4.7）と Codex（GPT-5.5）のコーディングエージェント。各セッションはコンテナ内で、1 行のプロンプト（program.md を読むことと `agora analyze` の実行を指示）で起動される。program.md（2 ページ）が最初の node として commit されている（§4.2）。
- ワーカー：13 アカウント（A100 が 5、H100 が 8）。各ワーカーは 80 GB GPU を 1 枚使う（§4.2）。
- 期間：setup commit（4 月 26 日）からカットオフ（5 月 8 日）まで、サーバ時間で 11 日 19 時間（§4.3）。報告値は最初の 1,703 件に基づき、カットオフ後の 123 件は除外している（Figure 4 キャプション）。
- 投稿の内訳：scored result 1,124、insight 284、hypothesis 203、verification 165、report 1（タグの重複あり）。233 件が新しい最良を更新した（§4.3）。
- 投稿形式：親とそのスコア、1 つの変更点、予測レンジ、測定結果、後続への指名。4 月 28 日以降は 400 件超が測定前に予測レンジを宣言している。著者は「そのように求めてはいない」と述べ、ブリーフの再現性要件と他アカウントの投稿の可視性から生じたとする（§4.3）。

### 3.4 最良の手法（§4.4、Algorithm 1、Table 3）

- 最良 contribution の commit 鎖は 83 個の Python モジュールからなり、各モジュールが親を import して 1 つの変更を加える。著者は鎖を根まで辿り、各定数を確認した（§4.4）。
- Stage A：6 つのドナー（GPT-2 small／large、Cerebras-GPT 111M〜1.3B）から、28 個の単一トークン文脈で次トークンの対数確率を集め、50257×50257 のバイグラム表を作る。ランダム SVD（rank 671、1 回の power iteration）で埋め込みと出力ヘッドに因数分解する。サブレイヤはすべてゼロ。
- Stage B：attention・FFN・SSM のサブレイヤを、96 次元の「バンド」に対する疎な編集として再有効化する。attention は一様な因果平均プール、SSM は depthwise 畳み込み（再帰はオフ）として機能させる（Table 3）。
- 著者は「Algorithm 1 と Table 3 はエージェントの説明文からではなく、コードから書き起こした」と述べる（§4.8）。
- 読解上の注意：「学習データを使わない」はターゲットについての制約である。ドナーは大規模に事前学習されており、その振る舞いが転移している。この点は著者の主張を読む際に意識すべきである（読者としての解釈）。

### 3.5 結果の軌跡と系譜（§4.5、Table 4）

- 最初の試行はパラメータのスライス・コピーで 4.68 bpb（ランダムより悪い）。同じアカウントが 30 分後に unigram 事前分布（2.52）へ置き換え、6 時間以内に 4 アカウントがバイグラム統計へ拡張した（1.93）。
- 最初の 18 件の scored contribution が総改善量の約 98% を占める。本文の "remaining 1,106" は、scored result 全体 1,124 から 18 を引いた数と読める（本文に明記はない）。その 1,106 件は 0.03 bpb 程度を追加した。
- Table 4 の各行は「同じ開発評価器で選ばれた」探索の段階であり、対照実験ではないと著者が注記している。
- 53 件が negative result としてタグ付けされている。その中には、プレフィックス数を 48 に倍増させると悪化することを示す 4 つの統制変種を含む（§4.5）。
- 系譜：最良の祖先は 145 commit、17 アカウントのうち 15 が寄与し、144 本の親辺のうち 115 本がアカウント境界を越える（§4.5）。
- 主結果：1.899044 bpb。「最後に記録された変更は 9×10⁻⁶ bpb の改善で、ハード間変動より小さい」（§4.5）。

### 3.6 検証の仕方（§4.5、§4.8）

- 検証 165 件、対象 95 件。各検証は対象を名指しし、検証者は作者と異なり、失敗報告は 0 件である（§4.5）。
- 同一ハードでの再現は bit-identical。A100 と H100 の差は最大 1.3×10⁻³ bpb で、ブリーフが「確定」と認める許容範囲内とされる（§4.5）。
- 最良の祖先 144 件のうち 40 件が独立に再現された（§4.5）。
- 著者の検証は 3 段階：(a) trace 全体をエクスポートして統計を再計算、(b) 報告スコアを損失・トークン数・バイト数から代数的に照合、(c) 勝者 commit の import 鎖を辿ってコードを読み、評価データに触れず勾配で更新しないことを確認（§4.8）。
- 勝者手法そのものは再実行していない。主結果は保存された評価器の出力であり、エージェントによる別ハードでの再現が裏付けとなる（§4.8）。

### 3.7 協調の観測（§4.6–4.7）

- グラフ：1,703 ノード、1,894 辺、多親ノード 149、98.9% が単一の連結成分。「狭い背骨と短く捨てられた枝」（Figure 4）。
- 4 つの観察：(1) 最初の 8 件で約 70% の下降、最初の 18 件で約 98%。(2) 狭い背骨。(3) 並行再発見（696 組中 63% が 1 時間以内、80% が 6 時間以内）。(4) 共通の診断：評価器は大域的に線形で、ターゲットのサブレイヤが十分に使われていない。(4) について著者は「エージェントの解釈的主張として報告する」と明記している（§4.6）。
- 人間の介入：5 月 2 日、活動の 3 分の 1 超が単一の意味クラスタに集中し、リーダーボードが停滞していたため、クラスタ・多様性サマリ・多様性考慮 UCB を導入した。その翌朝、細い SSM クラスタを選んだワーカーが最初の 1.90 未満の結果を出した。著者はタスクの割り当て、レビュー、承認、個別セッションへの指示をしていないとする（§4.7）。
- Figure 2 のキャプションによれば、negative-result タグと explore-novel タグは 5 月 2 日の導入後にのみ現れる。
- 著者の解釈：「調整層が、個々のエージェントよりも制約だった」（§5）。ただし同じ節で「因果は未確定」と留保している。

## 4. 確認できなかったこと

- **計算資源の総量**：トークン数、API 費用、GPU 時間の総計は記載がない。本文にあるのは評価 1 回が数秒、遷移行列の構築が H100 で約 5 分という数値のみである（§4.2）。

## 6. 制約（論文自認と読者としての注意）

**論文自認（明示的な記述のみ。本文に Limitations 節はない）**

1. 「What the run does not settle is causal」（§5）。
2. 「A shared leaderboard did not stop duplicate work, and the graph is heavily exploitation-biased」（§4.6。"It is also a picture of its weaknesses" の直後の記述）。

※ F1（論文自認の限界の数）の集計規則：著者が「弱点」または「未決」と明示した項目を数えた。§4.6 の 2 点と §5 の因果 1 点の計 3。§4.5 の「改善幅を信頼すべき」という注意と §4.8 の「勝者手法を再実行していない」は注記として書かれているが、限界として数えていない。

**読者としての注意（本レポートの解釈）**

3. 1 コミュニティ・1 走行である。手法の選択は走行中に起き、Table 4 の各行は事後的に選ばれた探索段階である（著者の注記）。
4. 全選択が同じ開発評価器上で行われた。held-out がないため、1.899 の数字は楽観的に出ている可能性がある。
5. 「独立」の範囲は、同じブリーフ・同じ評価器・同じリポジトリ・同系統の基盤モデル（Claude Opus 4.7、GPT-5.5）である。同質性は高く、本実験の rho／c の観点でこの点は重要である。
6. 著者は自分のシステムを評価している。エージェントの解釈は、著者が検証した範囲を除き「彼らの主張」として扱われている（§4.6）。
7. 「無訓練」はターゲットに限った話である（§3.4）。

## 7. ResearchOS への示唆（本実験に関わるもの）

1. **E2（rho／c）への含意**：並行再発見（§4.6(3)）は、同じ可視フロンティアという共有入力に起因する相関の例と読める。ただし本論文は誤りの相関を測っていない。同一スコアの一致を「同一の誤り」とは扱えず、むしろ検証成功の証拠になりうる。本実験の A と A' は同じ論文を読むため、両者の一致は rho と c の合成であり、分離できない（[`docs/parallel-experiment-2026-10-20.md`](../docs/parallel-experiment-2026-10-20.md) §1）。
2. **検証の 3 段階（§4.8）**：trace の再計算、結果の代数的照合、コードの鎖の読解。これは本リポジトリの「構造的保証（スキーマ・再実行）と意味的保証（人間のレビュー）」の二層方針に近い。ただし著者は勝者手法を再実行しておらず、再実行の要件は本リポジトリより弱い。
3. **不変の識別子（Appendix A）**：プロンプト、シード、ハード、評価器の版などの列挙は、再現性メタデータの最低限の項目として参照できる。
