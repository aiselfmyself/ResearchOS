# ResearchOS × GitSwarm 実験サマリ＆リポジトリ変遷ガイド

このレポートは、本セッションで行われた一連の実機検証において、**「各Workerが具体的に何をしたのか」**、そして**「リポジトリ全体が開始時からどのように進化したのか」**を、専門的なコードを読まなくても直感的に把握できるようにまとめたガイドです。

## 1. 3分でわかる！何が起きたのか（エグゼクティブサマリ）

1. **まっさらなリポジトリからスタート:**
   - 本日の開始時点では、このリポジトリには初期コミット（`README.md` のみ）しかありませんでした。
2. **GitHub Actions と GitSwarm の実機検証:**
   - クラウド上の GitHub と連携し、テストの自動実行（CI）、ブランチ操作、PR作成が正常に動作することを確認しました。
   - さらに、最新論文（arXiv:2610.04862）の「GitSwarm（分散型累積推論）」の仕組みを組み込み、自律エージェント群が推論を蓄積できることを実証しました。
3. **ユーザー構想「ResearchOS」の垂直統合実験:**
   - ユーザー様の構想である「研究オペレーティングシステム」のプロトタイプをリポジトリ内に構築。
   - 6つの異なる役割を持つAIワーカー（司令塔、探索役2名、批判役、監査役、統合役）が自律的に連携し、一次文献（arXiv）の探索から反証、監査、統合レポート執筆までを一気通貫で完結させました。
4. **結果:**
   - すべてのデータ・主張・反証・成果物が Git のコミットとして記録され、GitHub Actions による自動スキーマ検査を 100% パスした状態で、[Pull Request #6](https://github.com/aiselfmyself/ResearchOS/pull/6) に集約されています。

## 2. 各Workerは具体的に何をしたのか？（ロール別活動記）

今回の実験では、**「会話履歴に頼らず、Gitリポジトリを共有ノートとして自律的に作業する」**というルールのもと、6つの役割がリレー形式でバトンをつなぎました。

```text
[Supervisor (司令塔)]
        │ 計画と仮説を策定
        ▼
   ┌────┴────────────────────────┐
   ▼                             ▼
[Worker-01 (探索役1)]     [Worker-02 (探索役2)]
Stateless論文を調査       GitSwarm論文を調査
（メモリ外出しの利点）    （推論蓄積の利点 & 多数決の危険性を発見）
   └────┬────────────────────────┘
        ▼
   [Critic (批判・反証役)]
   「多数決は本当に正しいか？」を攻撃
   DuoDiscover論文を基に合意形成の脆さを反証
        ▼
   [Verifier (監査・検証役)]
   論文のURL、データ整合性、Git履歴を機械的に厳密チェック
        ▼
   [Integrator (統合役)]
   証拠と反証を総合し、完成版の研究レポートを執筆
```

### ① Supervisor（司令塔 / プランナー）
- **行ったこと:**
  - 研究課題「自律型AIエージェントにおける長期推論・分散協調アーキテクチャの最新動向」を読み込み、4つの具体的な調査ステップと2つの検証仮説（`HYP-001`, `HYP-002`）に分解しました。
- **残した成果物:**
  - `state/plan.md`（全体の研究計画書）
  - `state/hypotheses.jsonl`（検証すべき仮説データ）

### ② Worker-01（探索役 1：メモリ構造担当）
- **行ったこと:**
  - 「エージェントが長く考え続けると、会話履歴が長くなりすぎて過去の迷走に引きずられる」という課題を調査。
  - 最新論文『Stateless Language Agents』(arXiv:2610.07625) を読み解き、「会話履歴を溜め込まず、研究状態を外側のデータベース（ファイル）に逃がす」ことの有効性を実証しました。
- **残した成果物:**
  - 出典データ（`SRC-001`）と証拠（`EVD-001`）の登録
  - 主張（`CLM-001`: 外部化メモリの必要性）
  - 調査ノート `contributions/worker01_stateless_analysis.md`

### ③ Worker-02（探索役 2：分散協調担当）
- **行ったこと:**
  - 最新論文『GitSwarm: Decentralized Compounding Inference』(arXiv:2610.04862) を調査。
  - 過去の失敗（70.1%）も含めてGitコミットとして共有することで推論が劇的に蓄積されることを確認。
  - 同時に、**「GitSwarmの多数決推薦は、正解が機械判定できない文献調査では危険ではないか？」という境界的限界（Negative Finding）**を鋭く発見しました。
- **残した成果物:**
  - 出典データ（`SRC-002`）と証拠（`EVD-002`, `EVD-003`）
  - 主張（`CLM-002`: 推論蓄積の有効性、`CLM-003`: 多数決合意の脆弱性）
  - 調査ノート `contributions/worker02_gitswarm_and_limits.md`

### ④ Critic（批判・反証役 / フォーカサー）
- **行ったこと:**
  - Worker-02 の「多数決の危険性」という指摘を受け、**「AIエージェント同士の多数決は本当に信頼できるのか？」を徹底的に攻撃（Falsification）**。
  - 最新論文『DuoDiscover』(arXiv:2610.17184) を持ち出し、「同じモデル同士が合議すると、共通のバイアスで欺瞞的な誤りに収束する（評価ドリフト）」という反証証拠を突きつけました。
- **残した成果物:**
  - 出典データ（`SRC-003`）と反証データ（`EVD-004`）
  - 攻撃レビュー報告書 `verifications/falsification_report.md`

### ⑤ Verifier（監査・検証役 / ファクトチェッカー）
- **行ったこと:**
  - ここまでのワーカーが登録した全データ（論文のDOI、URL、引用文、データのリンク関係）にウソや矛盾がないかを厳密に監査。
  - さらに、Pythonの検証プログラム（`validate_researchos.py`）を実行し、Gitのコミットハッシュが実在するかまで機械的に確認しました。
- **残した成果物:**
  - 検証合格ログ `verifications/verifier_audit_log.md`
  - 4件の検証レコード（`VER-001`〜`VER-004`）

### ⑥ Integrator（統合役 / レポーター）
- **行ったこと:**
  - 単純な多数決をとるのではなく、**「確かな証拠があるか」「反証に耐えられたか」**を吟味。
  - 全ての主張を正式な結論（`status: supported`）へと昇格させ、初心者から研究者まで読める完成版の学術統合レポートを執筆しました。
- **残した成果物:**
  - 統合研究レポート `reports/researchos-pilot-synthesis-report.md`

| 領域 | 開始時点（Before） | 現在（After） |

## 4. このリポジトリに生まれた「新しい能力」

今回の実験を通じて、このリポジトリは単なる「コード置き場」から、**「自律型AI研究基盤（ResearchOS）」**へと生まれ変わりました。

1. **研究データの自己修復・自己検証能力:**
   - 誰か（人間またはAI）が間違ったデータや存在しない文献番号をコミットしようとすると、GitHub Actions が自動でエラーを出し、不正なデータ混入を防ぎます。
2. **記憶の不滅性（会話が切れても大丈夫）:**
   - チャット画面を閉じたり、別のAIモデルに切り替えたりしても、`state/` と `git log` を見れば、前回の続きから全く同じ文脈で作業を再開できます。
3. **失敗知見の再利用（負の結果の活用）:**
   - うまくいかなかったアプローチも `Outcome: negative` として保存されているため、次のAIワーカーが同じ無駄足を繰り返しません。
